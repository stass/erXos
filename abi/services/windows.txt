# The windows interface (docs/design-display.md, "The window tree"): an erx_fs grant of
# one display's window tree, which erx_winfs serves and a client mounts. Its operations
# are the file protocol's own, which no facet row names, so it declares none. A facet
# row's parameters are the grant's quotas: windows, the windows its holder may have at
# once; pixels, the bytes of its pixel area, which the display maps read-only and pays
# for; and snarf, whether its tree has the display's clipboard. session marks the grant
# of the display's session; the domain service alone sets it, from the start row that
# names the display, so no facet row may (property 18). A row that states no windows or
# pixels gets windows_default windows and a pixel area of windows_pixels_default bytes,
# one 1920 by 1080 x8r8g8b8 buffer, 8294400 bytes, rounded up to 8 MiB, and a row that
# states no snarf has no clipboard. windows_grant is property 18 of the
# manifest check (docs/design-system.md, "The manifest"): it sums each display's pixel
# areas within its display domain's outer budget, refuses session, and holds windows
# and snarf to their declared bounds; erx_winfs enforces windows and snarf at run time.
service windows 8
  parameter windows 1 u64 optional range 1 4096 checked_by windows_grant
  parameter pixels 2 u64 optional range 4096 1099511627776 checked_by windows_grant
  parameter snarf 3 boolean optional boolean checked_by windows_grant
  parameter session 4 boolean optional boolean checked_by windows_grant
limit windows_default u32 1
limit windows_pixels_default u64 8388608
# The window tree's wire (docs/design-display.md, "The window tree" and "Windows and
# buffers"), which erx_winfs and its windows serve and erx_win reads, so both sides take
# it from here. windows_tree is the tree's name in an attach; windows_file names a
# window's files in the order its directory lists them, each value the file's number in
# its qid. A window's coordinates are Plan 9's int, from windows_coord_min to
# windows_coord_max, written in fields of windows_field digits and a space; a side is
# from 1 to windows_side_max; a mouse record is windows_mouse_record bytes, its kind and
# four fields; a ctl or wctl line is at most windows_line_max bytes, a present
# names at most windows_present_rects rectangles, and each of a window's input queues
# holds at most windows_queue_bytes of records.
bytes windows_tree 7 value 77696e646f7773
enum windows_file u8
  value ctl 1
  value mouse 2
  value kbd 3
  value wctl 4
  value label 5
limit windows_coord_min i32 -2147483648
limit windows_coord_max i32 2147483647
limit windows_field u32 11
limit windows_side_max u32 16384
limit windows_mouse_record u32 49
limit windows_line_max u32 1024
limit windows_present_rects u32 16
limit windows_queue_bytes u32 4096
