# The block transport contract's bounds (docs/design-storage.md, "Data model"), erXos's
# choice, which every block transport keeps: virtio-blk's and the SD host controller's
# device processes and the USB Bulk-Only transport's core. erx_blk's calls to a transport
# wait blk_call_timeout_ms. A request still waiting blk_wait_limit_ms after its acceptance
# is answered {device, deadline} without being issued; one issued blk_in_flight_ms ago and
# not complete is a failure that ends its device process, or for a USB unit its medium.
# Their sum stays below blk_call_timeout_ms, so the transport answers before its caller
# gives up.
limit blk_call_timeout_ms u32 30000
limit blk_wait_limit_ms u32 10000
limit blk_in_flight_ms u32 18000
# The most sectors one SD host controller request moves, 16 KiB: a write of them by a card
# within its specification (31 blocks at 250 ms of busy and the last at 500 ms, 8.25 s)
# finishes inside blk_wait_limit_ms, so a request with one such request ahead of it is
# still issued, and inside blk_in_flight_ms. It is the SD transport's own limit; virtio-blk's follows from
# its pool buffer and USB's from the xHCI bulk buffer.
limit blk_sd_max_sectors u32 32
