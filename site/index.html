What if every Erlang process were an operating-system process?

erXos is an operating system built on that idea. Its drivers, file systems and services are Erlang processes, supervised and isolated by a small capability microkernel, and its shell feels like UNIX.

01 / The idea

One machine, one Erlang system.

Drivers, file systems and system services are Erlang processes, supervised like any other. When one crashes, its supervisor restarts it.

The machine stays open. From an Erlang shell you inspect, trace and change it, all the way down to kernel objects. That is the goal, and the design is built around it: a kernel that knows nothing of Erlang, and an Erlang system that runs the machine.

In erXos, Erlang's process is the operating system's process: one process space, one message system and one view of identity, supervision and inspection span every runtime.

G1

Secure by construction

Authority is a capability someone handed you. Knowing a pid, a path or a node name grants nothing.

G2

Millions of processes

Erlang processes are cheap to create and cheap to switch. erXos keeps them cheap.

G3

Crashes are routine

A driver wedges its device. It fails alone, its supervisor restarts it, and the machine carries on.

G4

A live machine

Upgrade a driver in place. Follow any process to the line of source it is executing.

G5

One kernel, many runtimes

The kernel hands out CPU time. ERTS comes first. C programs share the machine on the same terms.

G6

Cross-platform

AArch64 on QEMU first, then the Raspberry Pi 4 and 5. Other architectures are ports, not redesigns.

02 / Principles

Four rules shape every change.

P1

Erlang wherever practical

Erlang runs the drivers, the file systems, the network stack and the shell. C is for the kernel, device shims and per-byte work. Practical is the key word.

P2

Beauty and simplicity

A few concepts, used everywhere. A little speed is a fair price for a lot of simplicity.

P3

Declarative where it simplifies

One manifest says what the machine runs. The build checks it. Where a description is simpler than code, it replaces the code.

P4

UNIX look and feel

Shell, files, pipes, ps. FreeBSD programs, recompiled from source. UNIX is how the system looks, not what it is built on.

03 / Architecture

A small kernel. Everything else is a process.

The kernel knows threads, memory, capabilities and interrupts. It knows nothing of Erlang. Everything else runs in user mode, the runtimes included.

A domain is an address space with its own runtime. It is also an Erlang node. Processes in different domains link, monitor and message each other as Erlang processes always have. A crashed domain looks like a dead node.

A1

Two-level scheduling

The kernel grants CPU time. Each runtime schedules its own processes within that grant, without a kernel call.

A2

A budget for everything

Every kernel allocation is charged to a budget. Delete the budget, and everything charged to it goes too.

A3

Private namespaces

Straight from Plan 9. There is no global root, so a path is the visible face of a capability.

erXos stands on the shoulders of giants. Erlang/OTP gave it processes and supervision; L4 and Fiasco, the kernel; Plan 9, namespaces and files; QNX, UNIX on a microkernel; Genera, a whole machine open to inspection. What is new is how the pieces meet.

05 / Correctness

Checked against answers the code did not write.

A test only proves what it checks. So erXos compares its code with stock OTP, a bounded model checker and a weak-memory simulator, and each check says what it covered.

Most checks come with a deliberately broken twin or a seeded defect that they must catch, so a check that cannot fail gets noticed. These checks have limits. A model checker checks a model, not machine code. A litmus test checks a small program, not the compiled lane. A race detector finds data races but cannot show that a protocol is right.

C1

Stock OTP as the oracle

OTP 29.1.2's emulator, kernel, stdlib and compiler test suites run on erXos and on stock OTP, and the results are compared case by case. erXos's C library also runs musl's own tests.

C2

Weak memory, under herd7

Litmus tests of the lane's wake handshake and ring positions run under Arm's AArch64 model and RC11. With its fences the protocol must never reach the bad outcome. Without them it must.

C3

TLA+ models

TLC checks models of the lane, connections and links, each with seeded defects it must catch. Models for the host link, updates and the scheduler are planned and not written.

C4

CBMC

Bounded model checking of the budget arithmetic and the capability table's lookup, rights and slot closing, for every input within stated bounds.

C5

Fuzzing and sanitizers

The rule is a fuzz target for every parser of untrusted input, and the known gaps are tracked. Host tests of the C code run under AddressSanitizer and UndefinedBehaviorSanitizer, and concurrency tests under ThreadSanitizer.

C6

Rules the build enforces

Rules of the form “only X may do Y” fail the build on a new site. The stack depth of the C17 cores is computed from their call graph, and two clean builds of the production boot image must match byte for byte.

06 / Try it

The real thing, in your browser.

The console at the top of this page runs erXos itself. Press Boot erXos and your browser downloads the same boot image that QEMU runs, then starts it on v64, an AArch64 machine emulated in WebAssembly. The kernel, the system domain and the command shell all come up inside the page, in a few seconds.

Nothing runs on a server, and nothing you type leaves your machine. Reset starts the machine again from the same image.

T2

Then Erlang

T3

Look around

ls / lists the root of the namespace. ps lists the processes, which are Erlang processes. top shows them live under uptime, memory and run queue; Ctrl-C ends it. dmesg prints the system log from boot on.

T4

On the network

ifconfig shows the network device and the address it got by DHCP. ping -c 3 8.8.8.8 sends real ICMP through erXos's Erlang stack and driver. A small router emulated in this page answers every echo itself: no packet leaves your browser.
