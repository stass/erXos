# The development manifest of the Raspberry Pi 4 Model B on the stopgap
# (config/platforms/raspi4b.json; docs/plan.md, 1b-I): the system domain, two configured
# domains, storage and network, and the system principal's session template, from which the
# console starts root's session at boot (docs/design-system.md, "Booting"). The storage
# domain is QEMU virt's row (config/manifest/qemu-virt-development.txt, whose comment gives
# its memory, restarts and storage_ctl facet): an interpreter service domain that holds the
# platform record's sd unit, EMMC2 and the legacy SD controller that shares its line
# (docs/design-storage.md, "The SD controller's line"). The unit is named block, as on
# QEMU virt, because storage_ctl acts on that unit name. The legacy controller is of no
# kind a runtime drives, so the domain holds it with the unit and is given no record of it
# and no register window onto it, and no driver opens it (docs/design-shared-devices.md,
# "The unit rule"). erx_blk drives EMMC2's sdhci record with its SD device process
# (erx_blk_sd), which logs that the SD card is not driven when no card answers. The domain
# holds the card's data window and serves /data, littlefs on that partition, as the data
# facet, with the rows below. The network and display domains are described with their
# rows below.
#
# The system domain holds two units (docs/design-platforms.md, "Raspberry Pi 4 Model B"),
# of one register page of the board each: the console's, the mini UART's page, which it
# shares with the auxiliary SPI controllers that no driver here drives, and the host
# link's, the PL011s' page, of which the host link uses UART3. The console's driver is
# erx_mini_uart, which keeps the divisor the firmware set. The display domain holds the
# framebuffer's unit: the root reads the framebuffer the firmware set up, prints its line
# (docs/design-device-tree.md, "The lines") and writes the display domain its record.
#
# The shares, runtime limits and the session's limits are QEMU virt's development
# manifest's (config/manifest/qemu-virt-development.txt), whose comment gives their
# measurements. The system principal holds root's one session, 36 MiB and outer 1 MiB,
# and 1 MiB for the outer budget of a domain that has ended while another still holds a
# connection to it, as QEMU virt's comment explains; the storage domain, 30 MiB and outer
# 1 MiB; the network domain, 36 MiB and outer 1 MiB; and the display domain, 24 MiB and
# outer 1 MiB: 131 MiB in all. The system baseline is QEMU virt's 46 MiB. root_memory,
# 185 MiB, admits the baseline, the principal's 131 MiB, the SD controller's 1 MiB of DMA memory and GENET's 1 MiB of device
# memory with 6 MiB no one is promised, and lies well below what the smallest Pi 4 the
# record names leaves the root: RAM less fiasco_reserve is 890 MiB there.

# data: QEMU virt's rows (config/manifest/qemu-virt-development.txt, whose comment gives
# their max_request, in_flight and max_heap_size): one erx_fs grant of /data's tree for
# each grantee, the system domain and each session made from root's template, read-write
# and bound to the grantee's domain id. Each grantee mounts it at /data
# (docs/design-files.md, "A facet's mount"). A boot with no card on EMMC2 has no volume,
# so the storage domain provides no mint for data, the grants stay idle and /data answers
# eio. The session's grant is one of its quota of four connections and the storage
# domain's of two; the system domain's travels on the storage domain's system connection.

  server @domain.storage
  interface files

# network: QEMU virt's network domain row for row (config/manifest/qemu-virt-development.txt,
# whose comment explains its memory, connections and restarts), an interpreter service
# domain that holds the net unit, the platform record's GENET (docs/design-platforms.md,
# "The Ethernet controller's unit"), and runs the network stack
# (docs/design-network-stack.md, "Who holds the network device") over erx_genet, whose
# interface is genet0, as FreeBSD names genet(4)'s first unit. It serves net, a grant of
# the stack, to the system principal's sessions, since the system domain may hold none
# (docs/design-system.md, property 15), and network_ctl, its driver-control facet, which
# acts on genet0's link, to the system domain alone (property 8).
#
# Its 36 MiB is QEMU virt's measurement of the stack over erx_virtio_net; the stack over
# erx_genet is not measured on the Pi (docs/todo-performance.md).
#
# Its grant is the users share, one CPU of the 2,250 mcpu the system share's reserve
# leaves the configured domains (dom_system_reserve, liberx/system/dom_core.c).
#
# Its quota of two connections holds root's session and one more while a session is
# replaced; its system connection counts against no quota (life_connections,
# liberx/system/dom_life.c). At rest the machine holds six of its 11: the system
# connections of root's session and of the storage, network and display domains, and the
# session's data and net; the other five are the three a replacement session makes beside
# its predecessor's closing rows and the two a restarted configured domain makes, as on
# QEMU virt.
domain network
  principal @principal.system
  limits @limits.network
  kind service
  flags none
  runtime @artifact.emu
  release @artifact.network
  restarts 5
  restart_period_s 600

# apps: the start service's tree, /apps/ctl and /apps/rc.conf (docs/design-apps.md,
# "Interfaces"), for each session made from root's template: one erx_fs grant served by
# the system domain, bound to the session and ending with it, so it travels on the
# session's system connection and takes none of max_connections. Its max_request is
# files_max_frame_min (property 16), as for every files grant; a ctl write is one line of at most
# 4 KiB and rc.conf at most 64 KiB, so in_flight is small; max_heap_size, in words

# The display domain is QEMU virt's row (config/manifest/qemu-virt-development.txt, whose
# comment gives its share, limits and connections): an interpreter service domain that holds
# the platform record's framebuffer unit and runs the firmware framebuffer's driver,
# erx_firmware_fb, and the window system's screen (docs/design-display.md, "The display
# device"). It serves display, its window tree, which no facet grants, so a screen on
# HDMI 0 shows the empty layout's background. A boot whose firmware set up no framebuffer,
# QEMU's raspi4b model without the raspi4b suite's stand-in for the firmware among them,
# gives the domain no framebuffer record, and the domain runs without a screen. Its
# 24 MiB and the display share's 100 mcpu are QEMU virt's figures, measured on neither
# board (TODO.md).
domain display
  principal @principal.system
  limits @limits.display
  kind service
  flags none
  runtime @artifact.emu
  release @artifact.display
  restarts 5
  restart_period_s 600
  args "-- -root / -bindir /bin -progname erl -home / -nouser -nocookie -no_epmd -proto_dist erx"
# display: the display domain's window tree (docs/design-display.md, "A display's
