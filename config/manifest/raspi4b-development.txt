# The Raspberry Pi 4 Model B's part of its development manifest on the stopgap
# (config/platforms/raspi4b.json; docs/plan.md, 1b-I). The manifest is the records every
# board takes, config/manifest/development.txt, followed by these (Platform#manifest_source).
# Together they configure the system domain, three configured domains, storage, network and
# display, and the system principal's session template, from which the console starts root's
# session at boot (docs/design-system.md, "Booting"). This part holds the machine, the
# system principal, the units and windows of the board's devices and the network domain's
# row, whose driver is the board's. The common part holds the storage and display
# domains' rows, the shares, runtime limits and limits, and the services and facets; QEMU
# virt's part (config/manifest/qemu-virt-development.txt) gives their measurements.
#
# The storage domain, an interpreter service domain, holds the platform record's sd unit,
# EMMC2 and the legacy SD controller that shares its line (docs/design-storage.md, "The SD
# controller's line"). The unit is named block, as on QEMU virt, because storage_ctl acts
# on that unit name. The legacy controller is of no kind a runtime drives, so the domain
# holds it with the unit and is given no record of it and no register window onto it, and
# no driver opens it (docs/design-shared-devices.md, "The unit rule"). erx_blk drives
# EMMC2's sdhci record with its SD device process (erx_blk_sd), which logs that the SD card
# is not driven when no card answers. The domain holds the card's data window and serves
# /data, littlefs on that partition, as the data facet. A boot with no card on EMMC2 has no
# volume, so the storage domain provides no mint for data, the grants stay idle and /data
# answers eio.
#
# The system domain holds two units (docs/design-platforms.md, "Raspberry Pi 4 Model B"),
# of one register page of the board each: the console's, the mini UART's page, which it
# shares with the auxiliary SPI controllers that no driver here drives, and the host
# link's, the PL011s' page, of which the host link uses UART3. The console's driver is
# erx_mini_uart, which keeps the divisor the firmware set.
#
# The display domain holds the framebuffer's unit and runs the firmware framebuffer's
# driver, erx_firmware_fb, and the window system's screen (docs/design-display.md, "The
# display device"): the root reads the framebuffer the firmware set up, prints its line
# (docs/design-device-tree.md, "The lines") and writes the display domain its record, so a
# screen on HDMI 0 shows the empty layout's background. A boot whose firmware set up no
# framebuffer, QEMU's raspi4b model without the raspi4b suite's stand-in for the firmware
# among them, gives the domain no framebuffer record, and the domain runs without a
# screen. Its 24 MiB and the display share's 100 mcpu are QEMU virt's figures, measured on
# neither board (TODO.md).
#
# The system principal holds root's one session, 36 MiB and outer 1 MiB, and 1 MiB for
# the outer budget of a domain that has ended while another still holds a connection to
# it, as QEMU virt's comment explains; the storage domain, 30 MiB and outer 1 MiB; the
# network domain, 36 MiB and outer 1 MiB; and the display domain, 24 MiB and outer 1 MiB:
# 131 MiB in all. The system baseline is QEMU virt's 46 MiB. root_memory, 185 MiB, admits
# the baseline, the principal's 131 MiB, the SD controller's 1 MiB of DMA memory and
# GENET's 1 MiB of device memory with 6 MiB no one is promised, and lies well below what
# the smallest Pi 4 the record names leaves the root: RAM less fiasco_reserve is 890 MiB
# there.
principal system
  memory 137363456
  grant @share.users
  domains 5
  names 64
  default_limits @limits.native
  ceiling_limits @limits.native
machine
  flags development
  host "erxos"
  console "/soc/serial@7e215040"
  hostlink "/soc/serial@7e201600"
  platform "raspi4b"
  root_memory 193986560
  system_baseline 48234496
  system_share @share.system
  users_share @share.users
  system_principal @principal.system
  max_domains 5
  max_connections 11
  system_lane 4096
  system_queue 16384
  peer_held 4096
  system_reserve 250
  sealing none
  system_runtime_limits @runtime_limits.system
  native_limits @limits.native
  system_args "-- -root / -bindir /bin -progname erl -home / -boot /bin/start -user erx_console -erx_record console_driver erx_mini_uart -nocookie -no_epmd -proto_dist erx"
unit framebuffer
  placement "framebuffer"
  holder @domain.display
unit block
  placement "sd"
  holder @domain.storage
# data: the card's data partition, whose sectors the medium layout gives (partition 0,
# abi/medium.txt), read-write for the storage domain alone, as on QEMU virt.
window data
  holder @domain.storage
  device "/emmc2bus/mmc@7e340000"
  role data
  partition 0
  rights read,write
  image none
# network: QEMU virt's network domain row for row (config/manifest/qemu-virt-development.txt,
# whose comment explains its memory, connections and restarts), an interpreter service
# domain that holds the net unit, the platform record's GENET (docs/design-platforms.md,
# "The Ethernet controller's unit"), and runs the network stack
# (docs/design-network-stack.md, "Who holds the network device") over erx_genet, whose
# interface is genet0, as FreeBSD names genet(4)'s first unit. It serves net, a grant of
# the stack, to the system principal's sessions, since the system domain may hold none
# (docs/design-system.md, property 15), and network_ctl, its driver-control facet, which
# acts on genet0's link, to the system domain alone (property 8).
#
# Its 36 MiB is QEMU virt's measurement of the stack over erx_virtio_net; the stack over
# erx_genet is not measured on the Pi (docs/todo-performance.md).
#
# Its grant is the users share, one CPU of the 2,250 mcpu the system share's reserve
# leaves the configured domains (dom_system_reserve, liberx/system/dom_core.c).
#
# Its quota of two connections holds root's session and one more while a session is
# replaced; its system connection counts against no quota (life_connections,
# liberx/system/dom_life.c). At rest the machine holds six of its 11: the system
# connections of root's session and of the storage, network and display domains, and the
# session's data and net; the other five are the three a replacement session makes beside
# its predecessor's closing rows and the two a restarted configured domain makes, as on
# QEMU virt.
domain network
  principal @principal.system
  limits @limits.network
  kind service
  flags none
  runtime @artifact.emu
  release @artifact.network
  restarts 5
  restart_period_s 600
  args "-- -root / -bindir /bin -progname erl -home / -nouser -nocookie -no_epmd -proto_dist erx -erx_net interfaces {erx_genet,interfaces,[]} -erx_net runtime erx_net_erxos"
