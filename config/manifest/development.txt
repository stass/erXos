# data: one erx_fs grant of /data's tree for each grantee, read-write and bound to the
# grantee's domain id. Each grantee mounts it at /data (docs/design-files.md, "A facet's
# mount"); the system domain's travels on the storage domain's system connection. Its max_request is files_max_frame_min (property 16), not the
# largest 9P msize, 65560, since a request is measured as its encoded Erlang term, which
# for a 64 KiB write with its envelope is longer than that; in_flight caps the requests the grant holds at once; max_heap_size, in
# words (2 MiB), bounds the grant's process, which holds up to in_flight write requests of
# 64 KiB with their data. reductions and period_ns bind no erx_fs grant. The storage
# domain takes two connections, root's session and one more while a session is replaced,
# and four more, one for each app of QEMU virt's apps row, whose template the build
# grants packages,
# and root's session eight: data, net, the display and media, and one
# more for each while its server is replaced; a domain's system connection counts against no quota (life_connections,
# liberx/system/dom_life.c). The network domain takes two, as the storage domain does for sessions,
# and four more, one for each app of QEMU virt's apps row, whose template the build
# grants net; the display domain takes one for root's session, which display_root
# grants the display, and one more while that session is replaced, and one for each
# app of the board's apps row, whose template the build grants the display (its
# limits, in the board's part). Each board's machine
# record reckons its max_connections from these rows.

# The PCIe domain's rows, the same on every board, whose part places the unit of its
# bridge (docs/design-pcie.md, "The rows and the facets' limits"). Its
# release, pcie, boots erx_pcie's supervisor and the mint of its pcie facet, and its
# -eval starts the enumerator once init holds the ready answer's facets, pci_bus among
# them (docs/design-pcie.md, "Processes"). max_frame holds the widest answer it takes,
# targets' 69,957 bytes, and max_message_heap that answer's 14,580 decoded words several
# times over. Its memory, 25 MiB, is its largest use rounded up to a whole MiB, and 2 MiB
# of headroom, as the network row's: 5,750 pool pages, 22.5 MiB, at rest after the boot's
# walk and report and the pcie suite's open on QEMU virt (docs/design-pcie.md, "The rows and the
# facets' limits").
# Its grant, 50 mcpu on CPU 0, is a share of its own, sized for the start's walk and one
# set or reset per holder's change.
#
