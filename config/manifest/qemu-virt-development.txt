# QEMU virt's part of its development manifest, which follows the records every board
# takes, config/manifest/development.txt (Platform#manifest_source). The comment below
# describes the whole manifest and gives the measurements behind both parts' figures.
#
# The development manifest of QEMU virt: the system domain, seven configured domains,
# storage, network, web, display, pcie, usb and media, as docs/design-fiasco.md's "The Phase 1 manifest check"
# admits them, and the system principal's session template, from which the console starts root's
# session at boot (docs/design-system.md, "Boot"). The storage domain is an
# interpreter service domain that holds the block unit and its data, release and
# read-only system windows and runs the block driver and littlefs at /data
# (docs/design-stopgap.md, "littlefs in the storage domain"; design-fiasco.md, "The booted slot"); the
# slot writer's six windows, both slots' boot and system partitions and the two records,
# stay the system domain's (property 8). It serves storage_ctl, its driver-control facet,
# to the system domain alone (property 8; docs/design-system.md, "The holder's
# driver-control facet"), and data, an erx_fs grant of /data's tree, to the system
# domain and to root's session (property 16; docs/design-stopgap.md, "littlefs in the
# storage domain"). The network domain is an interpreter service domain that holds the net
# unit and runs the network stack (docs/design-network-stack.md, "Who holds the network
# device"). It serves net, a grant of the stack, to the system principal's sessions, since the
# system domain may hold none (docs/design-system.md, property 15), and network_ctl,
# its driver-control facet, to the system domain alone (property 8). The storage and
# network rows choose the interpreter over BeamAsm, the default for a service domain
# (docs/design-runtime.md, "BeamAsm"), because BeamAsm compiles each module it loads,
# which slows a boot that starts several runtimes on one CPU (docs/todo-performance.md,
# "every domain loads its own kernel and stdlib"). Where network throughput is
# measured, the network row runs BeamAsm: the net_device suite's exchange cell, whose
# TCP line measures it, boots the row on BeamAsm (NetDevice.manifest), and
# `tools/erx bench net-freebsd` runs the stack on stock OTP.
# The web domain is an
# interpreter service domain that runs the connection core of each browser connection
# the host tool carries (docs/design-web.md, "The host tool's front end"); it serves
# web, the relay of those connections, to the system domain, whose host link offers it
# to the host as its web facet. The display domain is an interpreter service domain that
# holds the display unit, the platform record's virtio-gpu, and runs its driver and the
# window system's screen (docs/design-display.md, "The display device"); it serves
# display, its window tree, which no facet grants, so it shows the empty layout's
# background. A boot that attaches no gpu leaves the gpu's transport empty, and the
# domain runs without a screen (erx_virtio_gpu). The PCIe domain, pcie, is an
# interpreter service domain that holds the ECAM bridge's unit, pcie, and with it every
# function's configuration space, and holds nothing else (docs/design-pcie.md, "The PCIe
# domain"); it serves pcie, its bridge facet, to the system domain alone, and takes
# pci_bus, the system domain's device service, which no other domain holds
# (docs/design-pcie.md, "Facets"). Its rows and their figures are the common part's, and
# its unit ends this part, followed by the USB domain's rows: usb is an interpreter service domain that holds the xhci unit,
# qemu-xhci by place behind the PCIe domain, and nothing else, and runs the USB stack,
# erx_usb (docs/design-usb.md, "Who holds a controller"); it takes pci, the device
# service's facet for its function (docs/design-pcie.md, "Facets"), and serves its drive
# disk0 to the media domain. The media domain's rows follow: media is an interpreter
# service domain that holds the window disk0 on the xhci function, the drive a stick put
# in takes, and nothing else, and serves media, the files of the drives it holds
# (docs/design-drives.md, "Manifest rows"); it runs nothing yet. Fixed
# medium roles carry partition 0, as docs/design-abi.md says.
# root_memory holds what the budgets below promise and an 8 MiB margin no one is
# promised; what RAM less fiasco_reserve leaves beside it is bootstrap's and the boot
# archive's, and the packer prints both figures for each image it builds. The system
# baseline, 46 MiB, holds ERTS at the shell and /tmp, whose cap is 4 MiB. ERTS
# sizes its tables and schedulers from runtime_limits and the system share
# (docs/design-runtime.md, "Starting a runtime"): at the Erlang shell, with 85
# processes and 213 modules, the system domain holds 9,268 liberx pool pages,
# 36.2 MiB (an Apple M3 Max host, HVF, QEMU 11.1.3, Homebrew clang 23.1.3, 4 guest
# CPUs, one boot of the interactive development image on 160 MiB of RAM, with this
# manifest's system baseline and the block driver and littlefs in the system domain);
# 1,000 more idle processes
# add about 4 MiB, and the rest of the baseline over ERTS and /tmp, 5.8 MiB, is the
# margin. The system principal's 337 MiB and 48 KiB holds root's one session, whose limits'
# memory is 36 MiB and outer 1 MiB, the storage domain, 30 MiB and outer 1 MiB, the
# network domain, 36 MiB and outer 1 MiB, the web domain, 24 MiB and outer 1 MiB, the
# display domain, 24 MiB and outer 97 MiB and 48 KiB (see below), the PCIe domain, 25 MiB and
# outer 1 MiB, the USB domain, 32 MiB and outer 1 MiB, the media domain, 25 MiB and outer 1 MiB, and 1 MiB for the outer budget of a domain
# that has ended while another still holds a connection to it: that outer budget is the library's until the survivor answers the
# connection's end (erx_domain_srv ended/3), and a session's next login or a
# configured domain's restart is admitted before that answer arrives. One such budget
# is the bound as long as one domain at a time ends and the survivor answers before its
# peer ends a second time; a second leftover refuses the next start
# (docs/todo-domains.md, "a refused restart is not retried"). The web and PCIe domains each hold a
# connection to the system domain alone, so their ends leave no such budget; the USB domain, which
# the display's usb_input and the media domain's drive grant connect to, and the media domain each
# leave their 1 MiB, which this 1 MiB holds; the display domain, which
# root's session holds a connection to, leaves its whole outer budget, which this 1 MiB
# does not hold (docs/todo-domains.md, "a display domain's end keeps its outer budget"). With it
# the baseline leaves root_memory the block device's 1 MiB, the network
# device's 256 KiB, the gpu's 9 MiB, the keyboard's and the tablet's 64 KiB each, the
# xhci function's 1 MiB of DMA memory and the 8 MiB margin no one is promised: the domain
# library charges a device's memory to the system's budget, not its holder's (dom_life.c,
# ERX_DOM_STEP_CONTIGUOUS).
# The web domain's 24 MiB is not measured yet: the bare release, loaded, on the
# interpreter, takes 18.3 MiB in the Footprint table below, and each of the host
# tool's four connections holds at most 1 MiB (docs/design-web.md, W8): about 23 MiB
# with erx_web's modules, which leaves about 1 MiB of headroom until the row is
# measured. Its grant, the web share, is 150 mcpu. The display domain's 24 MiB is not
# measured either, though the display_domain suite boots this row with a client; its
# grant, the display share, is a tenth of one CPU, to be sized from measurement. Its
# outer budget is 1 MiB and the four pixel areas of windows_pixels_default, 8 MiB, with
# their 4 KiB lanes that the apps row's four apps hold, since the build grants the app
# template the display, and eight more for the sessions of root's template that the
# system principal's domains quota lets live at once, which display_root grants it
# (development.txt), 64 MiB and 32 KiB in all: a grant
# adds its pixel area and lane to it (docs/design-system.md, "The manifest", property
# 18), a connection to the domain's quota and one to max_connections, as the
# display_domain suite adds them for its client (DisplayDomain.manifest). The two grants and the PCIe, USB and media
# domains' 50, 100 and 50 mcpu come out of what the system share's reserve leaves beside the storage
# and network domains' 900 mcpu each, and leave 75 mcpu (property 13); the web, display, pcie, usb and media
# shares' cpuset, CPU 0 alone, gives each domain one scheduler. The gpu's 9 MiB of DMA memory is made at every boot, a gpu attached or not,
# since the manifest places the device; with it the devices' 11.375 MiB take the
# contiguous pool to its 16 MiB bound (docs/design-fiasco.md, "The pool"), which the
# boot keeps beside root_memory, and leave 4.625 MiB for any other device's memory.
# The storage domain's 30 MiB is its
# use rounded up to a whole MiB: 7,635 pool pages, 29.8 MiB, with BeamAsm (more than the
# interpreter the row runs: docs/design-shared-code.md, DlJitExtra), erx_blk
# and erx_storage running and /data mounted, at rest, measured as Footprint measures
# (the root's pool pages in use with the domain up minus those once it has ended;
# the block_device suite's medium boot, 512 MiB, HVF, 1 guest CPU, an Apple M3 Max
# host, QEMU 11.1.3, Homebrew clang 23.1.3). The users share's cpuset of four CPUs
# gives it four schedulers and four dirty CPU schedulers; with a cpuset of one CPU it
# took 5,629 pages, 22.0 MiB.
# A session's runtime starts with its runtime_limits' max_message_heap of 131072
# words and the allocator flags every runtime starts with (docs/design-runtime.md,
# "Memory"), which shrink the carriers of every allocator but literal_alloc and
# temp_alloc. A test image that needs more names a larger machine
# (ProductionImage::Machine), which grows root_memory, the baseline and /tmp's cap.
# The website's manifest is made from this one at build time: it leaves out the
# domains the platform record's site_leaves_out names, each with the records only it
# uses and the room it took (Platform#site_manifest_source; docs/design-fiasco.md,
# "The Phase 1 manifest check").
#
# What a driver domain costs (tools/lib/erx/medium_boot.rb, Footprint; an Apple M3 Max
# host, HVF, QEMU 11.1.3, Homebrew clang 23.1.3, 4 guest CPUs, the 768 MiB medium
# machine, interpreter ERTS domains with 1,024 processes, 16,384 atoms and tmp 0, at
# rest; one run, the system domain's /tmp cap 4 MiB). A domain's cost is the root's
# pool pages in use with the domain up minus the pages once it has stopped; the pool is
# the Fiasco backend's partial figure.
#
#   release (applications)                      pool pages    MiB
#   bare (kernel stdlib erx erx_files)          4,568         17.8
#   blk (bare + erx_blk, loaded)                4,568         17.8
#   net (bare + erx_net, erx_net_client)        4,568         17.8
#   the bare release, loaded                    4,696         18.3
#   the blk release, its 9 modules loaded       4,760         18.6
#   the net release, its 82 modules loaded      5,240         20.5
#   system domain at the shell, /tmp 4 MiB      8,072         31.5
#
# The archive of the Footprint image is 48,967,680 bytes (46.70 MiB): the system release
# 21.70 MB, the one domain release with the boot scripts of all its names 12.24 MB, the
# boot files 5.09 MB and the interpreter and BeamAsm runtime images 3.72 and 4.29 MB.
#
# The system row is read before the domains of the run start; it is 7,912 pages (30.9
# MiB) once they have stopped. Every
# domain maps ERTS's 2.84 MiB of text and 0.60 MiB of read-only data from the archive's
# pages, shared by all of them, so a domain's 17.8 MiB is ERTS's data and bss, 0.72 MiB,
# of which it has its own copy; the allocators' carriers, 14.0 MiB, of which
# erlang:memory() reports 10.4 MiB in use (ll_alloc holds 8.75 MiB for 5.9 MiB of
# code, literal_alloc 2.0 MiB); and 3.1 MiB left for the threads' stacks (one
# scheduler, one dirty CPU scheduler, two dirty IO schedulers and one async thread)
# and the rest. Release files are mapped from the archive's pages, so they cost the
# domain nothing. The archive holds one domain release, each application's files
# once, with a boot script per name, so a name costs it only the files of
# applications no other script boots and its script. Loading the modules adds 128
# pages even to the bare release, which has none to load: carriers the step's work
# frees stay in mseg_alloc's cache of two. Loading erx_blk's 9 modules adds 0.2 MiB of
# memory and 192 pages; erx_net's and erx_net_client's 82 add 1.3 MiB of memory
# and 672 pages. erx_net and erx_blk are loaded, not started: the network application
# needs the system domain's local transport and a device needs its holder, so these
# are the domains at rest. The system domain's carriers hold 22.9 MiB for 16.1 MiB in
# use. A tmp cap above 0 does not move a domain's figure (the bare release with a
# 4 MiB cap, created last, took 4,568 pages as the others did): the cap is charged on
# use, not up front.
#
# The development machine admits the system domain, root's session and the storage, network,
# web, display, PCIe, USB and media domains. Admission charges budgets, not use: the system baseline, 46 MiB,
# the system principal's 337 MiB and 48 KiB (root's session, 36 MiB and outer 1 MiB, the storage
# domain, 30 MiB and outer 1 MiB, the network domain, 36 MiB and outer 1 MiB, the web
# domain, 24 MiB and outer 1 MiB, the display domain, 24 MiB and outer 97 MiB and 48 KiB, the PCIe
# domain, 25 MiB and outer 1 MiB, the USB domain, 32 MiB and outer 1 MiB, the media domain,
# 25 MiB and outer 1 MiB, and an ended domain's
# outer 1 MiB), the apps row's 131 MiB and the devices' 11.375 MiB
# promise all of root_memory but its 8 MiB margin. The network
# domain's 36 MiB is its use rounded up to a whole MiB, 34 MiB, and 2 MiB of headroom:
# 8,603 pool pages, 33.6 MiB, with BeamAsm (more than the interpreter the row runs) and
# the users share's four schedulers, after
# root's session has run ping -c 3 and echoed 1 MiB over TCP through it, measured as
# Footprint measures (docs/design-network-stack.md, the network domain's memory; the
# net_device suite's network-domain cell, a 768 MiB machine, HVF, 1 guest CPU, an Apple
# M3 Max host, QEMU 11.1.3, Homebrew clang 23.1.3). The storage and network domains each
# take the users share, 900 mcpu, the web domain 150 mcpu, the display domain 100, the
# PCIe domain 50, the USB domain 100 and the media domain 50: 2,250 mcpu of the 2,325 that the
# system share's reserve leaves the configured domains, 3,100 less a quarter of it (system_reserve 250;
# dom_system_reserve, liberx/system/dom_core.c), so another configured domain's grant
# beyond 75 mcpu comes out of these.
# In use, the root's pool holds the system domain's 31.5 MiB
# (36.2 MiB at the interactive shell of the development image), the session's about
# 19 MiB (the bare release's 18.3 MiB and the shell's modules), the storage domain's
# 29.8 MiB, the network domain's 33.6 MiB, the web domain's about 19 MiB and the PCIe
# domain's 22.5 MiB: about 155 to 160 MiB beside the display, USB and media domains', which are
# not measured. With the devices' 11.375 MiB that leaves about 362 to 367 MiB of
# root_memory, less the display, USB and media domains' use, unused. RAM less
# root_memory is left to Fiasco's kernel memory (fiasco_reserve, about 6% of RAM,
# its boot log's "Reserved N MiB as kernel memory"), its image and sigma0, the
# archive, the root's image (4.8 MiB) and the device tree's 1 MiB; each MiB the
# archive grows takes a MiB of what sigma0 offers the root. The packer refuses an
# archive that leaves too little, counting what the boot keeps from the platform
# record (docs/design-fiasco.md, "The root startup rule"), and prints the largest
# archive this root_memory leaves room for. A larger machine grows root_memory with
# the system's growth (ProductionImage::Machine), never by an edit here.
#
# The image release is the system release's EROFS image in the slot, with no
# hash tree; the packer takes its extent from the image it builds
# (ReleaseMedium.image), and the storage domain holds a read-only window on it.
#
# The storage, network, web, display, PCIe, USB and media domains restart at most 5 times in 600 s, where a restart
# after a boot timeout counts, however long ago, until a boot that reached ready ends, so a boot
# that hangs, stopped only at each timeout, is left down after 5 restarts in a row whatever the
# machine's boot timeout (docs/design-system.md, "Boot").

# The USB domain's rows (docs/design-usb.md, "Who holds a controller", "The rows"). Its
# release, usb, boots erx_usb, whose supervisor starts the places and the mint of the

# facets, pci among them, reads the domain's xhci function record and starts the

# that serves the service media, and the holder of the USB domain's drive disk0, the one
# drive on the xhci controller's row, so a stick put in takes disk0
# (docs/design-usb.md, "Mass storage reaches the file servers"). Its release, media,
# names erx_fat and erx_media and neither erx_storage nor erx_blk. Its memory and grant
# are sized as the PCIe domain's, an interpreter domain with nothing started beyond the
# base: 25 MiB and 50 mcpu on CPU 0, a share of its own, out of what the system share's
# reserve leaves; it runs in the interactive band, as the domains that serve people do,
# and its three connections beside its system connection are the USB domain's drive
# grant and root's session's media facet with one more while that session is replaced.
runtime_limits media
  max_frame 131072
  max_message_heap 131072
  funnel_depth 64
  exports 256
  tmp 0
  overlay 0
  atoms 16384
  foreign_atoms 1024
  processes 1024
share media
  quota_ns 500000
  period_ns 10000000
  cpuset 1
  capacity_mcpu 50
  capacity_first 0
  slice_us 1000
  grace_us 5
  base 16
  ceiling 31
  flags none
limits media
  memory 26214400
  outer 1048576
  grant @share.media
  spaces none
  lane 4096
  connections 3
  crash 0
  flags none
  runtime_limits @runtime_limits.media
  band interactive
  peer_held 4096
  peer_held_total 4096
domain media
  principal @principal.system
  limits @limits.media
  kind service
  flags none
  runtime @artifact.emu
  release @artifact.media
  restarts 5
  restart_period_s 600
  args "-- -root / -bindir /bin -progname erl -home / -nouser -nocookie -no_epmd -proto_dist erx"
service media
  server @domain.media
  interface files
# media: every drive's files, which root's session mounts at /media (docs/design-drives.md,
# DR-R8 and "Mounting it"): the system principal's session template holds the one media
# facet, with the default rights rw, so root may read and change a stick and nothing runs
# from it. Its quantities are data_session's, a files grant's (development.txt).
facet media
  grantee @session.system
  service @service.media
  operations none
  max_request 131072
  in_flight 16
  reductions 100000
  period_ns 1000000000
  max_heap_size 262144
window disk0
  holder @domain.media
  device "/pcie@10000000:0:2:0"
  role drive
  image none
  drive disk0
