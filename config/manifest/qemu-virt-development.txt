# The development manifest of QEMU virt: the system domain, configured with no
# other domain, as docs/design-stopgap.md's "The Phase 1 manifest check" admits
# it, and the system principal's session template, from which the console starts
# root's session at boot (docs/design-system.md, "Booting"). Fixed
# medium roles carry partition 0, as docs/design-abi.md says. The machine is
# QEMU virt with 160 MiB of RAM (config/platforms/qemu-virt.json), small for the
# browser emulator yet roomy at the shell; root_memory, 96.25 MiB, leaves 47.75 MiB
# below RAM less fiasco_reserve for bootstrap and the boot archive. The system
# baseline, 46 MiB, holds ERTS at the shell and /tmp, whose cap is 4 MiB. ERTS
# sizes its tables and schedulers from runtime_limits and the system share
# (docs/design-runtime.md, "Starting a runtime"): at the Erlang shell, with 85
# processes and 213 modules, the system domain holds 9,268 liberx pool pages,
# 36.2 MiB (an Apple M3 Max host, HVF, QEMU 11.1.3, Homebrew clang 23.1.3, 4 guest
# CPUs, one boot of the interactive development image); 1,000 more idle processes
# add about 4 MiB, and the rest of the baseline over ERTS and /tmp, 5.8 MiB, is the
# margin. The system principal's 37 MiB holds root's one session, whose limits'
# memory is 36 MiB and outer 1 MiB; with it the baseline leaves root_memory the
# block device's 1 MiB, the network device's 256 KiB and 12 MiB no one is promised.
# A session's runtime starts with its runtime_limits' max_message_heap of 131072
# words and the allocator flags every runtime starts with (docs/design-runtime.md,
# "Memory"), which shrink the carriers of every allocator but literal_alloc and
# temp_alloc. A test image that needs more names a larger machine
# (ProductionImage::Machine), which grows root_memory, the baseline and /tmp's cap.
#
# What a driver domain costs (tools/lib/erx/medium_boot.rb, Footprint; an Apple M3 Max
# host, HVF, QEMU 11.1.3, Homebrew clang 23.1.3, 4 guest CPUs, the 768 MiB medium
# machine, interpreter ERTS domains with 1,024 processes, 16,384 atoms and tmp 0, at
# rest; two runs, the system domain's /tmp cap 16 MiB in one and 4 MiB in the other).
# A domain's cost is the root's pool pages in use with the domain up minus the pages
# once it has stopped; the pool is a stopgap's partial figure. Each range is the two
# runs' figures.
#
#   release (applications)                      pool pages    MiB
#   bare (kernel stdlib erx erx_files)          4,536-4,568   17.7-17.8   archive 11.05 MB
#   storage (bare + erx_blk, loaded)            4,566-4,598   17.8-18.0   archive +0.05 MB
#   network (bare + erx_net, erx_net_client)    4,568-4,600   17.8-18.0   archive +1.11 MB
#   the storage release, its 9 modules loaded   4,918-4,950   19.2-19.3
#   the network release, its 82 modules loaded  5,496-5,528   21.5-21.6
#   system domain at the shell, /tmp 16 MiB     8,108         31.7
#   system domain at the shell, /tmp 4 MiB      8,203         32.0
#
# The system rows are read after the domains of the run have ended and stopped. Every
# domain maps ERTS's 2.84 MiB of text and 0.60 MiB of read-only data from the archive's
# pages, shared by all of them, so a domain's 17.8 MiB is ERTS's data and bss, 0.72 MiB,
# of which it has its own copy; the allocators' carriers, 14.0 MiB, of which
# erlang:memory() reports 10.5 MiB in use (ll_alloc holds 8.75 MiB for 5.9 MiB of
# code, literal_alloc 2.0 MiB); and 3.1 MiB left for the threads' stacks (one
# scheduler, one dirty CPU scheduler, two dirty IO schedulers and one async thread)
# and the rest. Release files are mapped from the archive's pages, so they cost the
# domain nothing. The archive holds one domain release, each application's files
# once, with a boot script per name, so a name costs it only the files of
# applications no other script boots and its script: the archive column is the
# domain release's bytes, and the session script's erx_shell and erx_session add
# 0.50 MB more. Loading the modules adds 192 pages even to
# the bare release, which has none to load: carriers the step's work frees stay in
# mseg_alloc's cache of two. Loading erx_blk's 9 modules adds 0.5 MiB of memory and
# 320-384 pages; erx_net's and erx_net_client's 82 add 1.7 MiB of memory and 928
# pages. erx_net and erx_blk are loaded, not started: the network application needs
# the system domain's local transport and a device needs its holder, so these are the
# domains at rest. The system domain's carriers hold 22.7 MiB for 16.1-16.5 MiB in
# use. A tmp cap above 0 does not move a domain's figure beyond the runs' spread (the
# bare release with a 4 MiB cap, created last, took 4,568 and 4,600 pages, as the
# storage and network releases did): the cap is charged on use, not up front.
#
# The 160 MiB machine does not hold the system domain, the root's session at 36 MiB, a
# storage domain and a network domain. At rest they need about 108 MiB of pool
# (36 + 36 + 18 + 18) against root_memory's 96.25 MiB, and the archive of the
# Footprint image, which carries the system release, the one domain release (bare,
# storage, network and session scripts) and the interpreter and BeamAsm runtime
# images, is 49,545,216 bytes (47.25 MiB) against the 47.75 MiB the machine leaves
# for it and the bootstrap: about 171 MiB in all with the Fiasco reserve's 16 MiB.
# Admission charges budgets, not use, and the system baseline is
# 46 MiB, so the shortfall is larger. What machine the driver domains need is for
# Footprint to measure on one tree with the shared segments and the one domain release.
#
# The image release is the system release's EROFS image in the slot, with no
# hash tree; the packer takes its extent from the image it builds
# (ReleaseMedium.image), and the system domain holds a read-only window on it.
