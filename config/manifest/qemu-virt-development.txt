# The development manifest of QEMU virt: the system domain, three configured domains,
# storage, network and web, as docs/design-stopgap.md's "The Phase 1 manifest check"
# admits them, and the system principal's session template, from which the console starts root's
# session at boot (docs/design-system.md, "Booting"). The storage domain is an
# interpreter service domain that holds the block unit and its data and release
# windows and runs the block driver and littlefs at /data (docs/design-stopgap.md,
# "littlefs in the storage domain"); the slot writer's four windows stay the
# system domain's (property 8). It serves storage_ctl, its driver-control facet,
# to the system domain alone (property 8; docs/design-system.md, "The holder's
# driver-control facet"), and data, an erx_fs grant of /data's tree, to the system
# domain and to root's session (property 16; docs/design-stopgap.md, "littlefs in the
# storage domain"). The network domain is an interpreter service domain that holds the net
# unit and runs the network stack (docs/design-network-stack.md, "Who holds the network
# device"). It serves net, a grant of the stack, to the system principal's sessions, since the
# system domain may hold none (docs/design-system.md, property 15), and network_ctl,
# its driver-control facet, to the system domain alone (property 8). The storage and
# network rows choose the interpreter over BeamAsm, the default for a service domain
# (docs/design-runtime.md, "BeamAsm"), because BeamAsm compiles each module it loads,
# which slows a boot that starts several runtimes on one CPU (docs/todo-performance.md,
# "every domain loads its own kernel and stdlib"). Where network throughput is
# measured, the network row runs BeamAsm: the net_device suite's exchange cell, whose
# TCP line measures it, boots the row on BeamAsm (NetDevice.manifest), and
# `tools/erx bench net-freebsd` runs the stack on stock OTP.
# The web domain is an
# interpreter service domain that runs the connection core of each browser connection
# the host tool carries (docs/design-web.md, "The host tool's front end"); it serves
# web, the relay of those connections, to the system domain, whose host link offers it
# to the host as its web facet. Fixed
# medium roles carry partition 0, as docs/design-abi.md says. The machine is
# QEMU virt with 256 MiB of RAM (config/platforms/qemu-virt.json), small for the
# browser emulator yet roomy at the shell; root_memory, 186.25 MiB, leaves 53.75 MiB
# below RAM less fiasco_reserve for bootstrap and the boot archive. The system
# baseline, 46 MiB, holds ERTS at the shell and /tmp, whose cap is 4 MiB. ERTS
# sizes its tables and schedulers from runtime_limits and the system share
# (docs/design-runtime.md, "Starting a runtime"): at the Erlang shell, with 85
# processes and 213 modules, the system domain holds 9,268 liberx pool pages,
# 36.2 MiB (an Apple M3 Max host, HVF, QEMU 11.1.3, Homebrew clang 23.1.3, 4 guest
# CPUs, one boot of the interactive development image on 160 MiB of RAM, with this
# manifest's system baseline and the block driver and littlefs in the system domain);
# 1,000 more idle processes
# add about 4 MiB, and the rest of the baseline over ERTS and /tmp, 5.8 MiB, is the
# margin. The system principal's 131 MiB holds root's one session, whose limits'
# memory is 36 MiB and outer 1 MiB, the storage domain, 30 MiB and outer 1 MiB, the
# network domain, 36 MiB and outer 1 MiB, the web domain, 24 MiB and outer 1 MiB, and
# 1 MiB for the outer budget of a domain that has ended while another still holds a
# connection to it: that outer budget is the library's until the survivor answers the
# connection's end (erx_domain_srv ended/3), and a session's next login or a
# configured domain's restart is admitted before that answer arrives. One such budget
# is the bound as long as one domain at a time ends and the survivor answers before its
# peer ends a second time; a second leftover refuses the next start
# (TODO.md, "a refused restart is not retried"). The web domain holds a connection to
# the system domain alone, so its end leaves no such budget. With it the
# baseline leaves root_memory the block device's 1 MiB, the network device's 256 KiB
# and 8 MiB no one is promised.
# The web domain's 24 MiB is not measured yet: the bare release, loaded, on the
# interpreter, takes 18.3 MiB in the Footprint table below, and each of the host
# tool's four connections holds at most 1 MiB (docs/design-web.md, W8): about 23 MiB
# with erx_web's modules, which leaves about 1 MiB of headroom until the row is
# measured. Its grant, the web share, is a quarter of one CPU, what the system share's
# reserve leaves beside the storage and network domains' one CPU each (property 13).
# The storage domain's 30 MiB is its
# use rounded up to a whole MiB: 7,635 pool pages, 29.8 MiB, with BeamAsm (more than the
# interpreter the row runs: docs/design-shared-code.md, DlJitExtra), erx_blk
# and erx_storage running and /data mounted, at rest, measured as Footprint measures
# (the root's pool pages in use with the domain up minus those once it has ended;
# the block_device suite's medium boot, 512 MiB, HVF, 1 guest CPU, an Apple M3 Max
# host, QEMU 11.1.3, Homebrew clang 23.1.3). The users share's cpuset of four CPUs
# gives it four schedulers and four dirty CPU schedulers; with a cpuset of one CPU it
# took 5,629 pages, 22.0 MiB.
# A session's runtime starts with its runtime_limits' max_message_heap of 131072
# words and the allocator flags every runtime starts with (docs/design-runtime.md,
# "Memory"), which shrink the carriers of every allocator but literal_alloc and
# temp_alloc. A test image that needs more names a larger machine
# (ProductionImage::Machine), which grows root_memory, the baseline and /tmp's cap.
#
# What a driver domain costs (tools/lib/erx/medium_boot.rb, Footprint; an Apple M3 Max
# host, HVF, QEMU 11.1.3, Homebrew clang 23.1.3, 4 guest CPUs, the 768 MiB medium
# machine, interpreter ERTS domains with 1,024 processes, 16,384 atoms and tmp 0, at
# rest; one run, the system domain's /tmp cap 4 MiB). A domain's cost is the root's
# pool pages in use with the domain up minus the pages once it has stopped; the pool is
# a stopgap's partial figure.
#
#   release (applications)                      pool pages    MiB
#   bare (kernel stdlib erx erx_files)          4,568         17.8
#   blk (bare + erx_blk, loaded)                4,568         17.8
#   net (bare + erx_net, erx_net_client)        4,568         17.8
#   the bare release, loaded                    4,696         18.3
#   the blk release, its 9 modules loaded       4,760         18.6
#   the net release, its 82 modules loaded      5,240         20.5
#   system domain at the shell, /tmp 4 MiB      8,072         31.5
#
# The archive of the Footprint image is 48,967,680 bytes (46.70 MiB): the system release
# 21.70 MB, the one domain release with the boot scripts of all its names 12.24 MB, the
# boot files 5.09 MB and the interpreter and BeamAsm runtime images 3.72 and 4.29 MB.
#
# The system row is read before the domains of the run start; it is 7,912 pages (30.9
# MiB) once they have stopped. Every
# domain maps ERTS's 2.84 MiB of text and 0.60 MiB of read-only data from the archive's
# pages, shared by all of them, so a domain's 17.8 MiB is ERTS's data and bss, 0.72 MiB,
# of which it has its own copy; the allocators' carriers, 14.0 MiB, of which
# erlang:memory() reports 10.4 MiB in use (ll_alloc holds 8.75 MiB for 5.9 MiB of
# code, literal_alloc 2.0 MiB); and 3.1 MiB left for the threads' stacks (one
# scheduler, one dirty CPU scheduler, two dirty IO schedulers and one async thread)
# and the rest. Release files are mapped from the archive's pages, so they cost the
# domain nothing. The archive holds one domain release, each application's files
# once, with a boot script per name, so a name costs it only the files of
# applications no other script boots and its script. Loading the modules adds 128
# pages even to the bare release, which has none to load: carriers the step's work
# frees stay in mseg_alloc's cache of two. Loading erx_blk's 9 modules adds 0.2 MiB of
# memory and 192 pages; erx_net's and erx_net_client's 82 add 1.3 MiB of memory
# and 672 pages. erx_net and erx_blk are loaded, not started: the network application
# needs the system domain's local transport and a device needs its holder, so these
# are the domains at rest. The system domain's carriers hold 22.9 MiB for 16.1 MiB in
# use. A tmp cap above 0 does not move a domain's figure (the bare release with a
# 4 MiB cap, created last, took 4,568 pages as the others did): the cap is charged on
# use, not up front.
#
# The 256 MiB machine admits the system domain, root's session and the storage, network
# and web domains. Admission charges budgets, not use: the system baseline, 46 MiB,
# the system principal's 131 MiB (root's session, 36 MiB and outer 1 MiB, the storage
# domain, 30 MiB and outer 1 MiB, the network domain, 36 MiB and outer 1 MiB, the web
# domain, 24 MiB and outer 1 MiB, and an ended domain's outer 1 MiB) and the devices'
# 1.25 MiB promise 178.25 MiB of root_memory's 186.25 MiB, which leaves 8 MiB no one is
# promised. The network
# domain's 36 MiB is its use rounded up to a whole MiB, 34 MiB, and 2 MiB of headroom:
# 8,603 pool pages, 33.6 MiB, with BeamAsm (more than the interpreter the row runs) and
# the users share's four schedulers, after
# root's session has run ping -c 3 and echoed 1 MiB over TCP through it, measured as
# Footprint measures (docs/design-network-stack.md, the network domain's memory; the
# net_device suite's network-domain cell, a 768 MiB machine, HVF, 1 guest CPU, an Apple
# M3 Max host, QEMU 11.1.3, Homebrew clang 23.1.3). The storage and network domains each
# take a whole CPU of the users share and the web domain a quarter of one, the 2,250 mcpu
# the system share's reserve leaves the configured domains (dom_system_reserve,
# liberx/system/dom_core.c). In use, the root's pool holds the system domain's 31.5 MiB
# (36.2 MiB at the interactive shell of the development image), the session's about
# 19 MiB (the bare release's 18.3 MiB and the shell's modules), the storage domain's
# 29.8 MiB, the network domain's 33.6 MiB and the web domain's about 19 MiB: about 133
# to 138 MiB, which leaves about 48 to 53 MiB of root_memory unused. RAM less
# root_memory leaves 69.75 MiB to Fiasco's kernel memory, 16 MiB at 256 MiB (its boot
# log's "Reserved 16 MiB as kernel memory", the production image's 1-CPU HVF cell on
# the Apple M3 Max host, QEMU 11.1.3), its image and sigma0, the archive, the
# root's image (4.7 MiB) and the device tree's 1 MiB. root_memory keeps about 1.4 MiB
# below what sigma0 offers the root, as on 192 MiB with 126.25 (sigma0 offered about
# 127.6 MiB there, the session suite's image on the Apple M3 Max host, HVF, QEMU
# 11.1.3): it grows by 30 MiB with each 32 MiB of RAM because Fiasco's kernel memory
# grows by 2.
#
# The image release is the system release's EROFS image in the slot, with no
# hash tree; the packer takes its extent from the image it builds
# (ReleaseMedium.image), and the storage domain holds a read-only window on it.
#
# The storage, network and web domains restart at most 5 times in 600 s: a boot that
# hangs is stopped after the default 60 s boot timeout, so a shorter period would never
# see 5 of them and would restart a hung domain without end.

# data: one erx_fs grant of /data's tree for each grantee, read-write and bound to the
# grantee's domain id. Its max_request is files_max_frame_min (property 16), not the
# largest 9P msize, 65560, since a request is measured as its encoded Erlang term, which
# for a 64 KiB write with its envelope is longer than that; in_flight caps the requests the grant holds at once; max_heap_size, in
# words (2 MiB), bounds the grant's process, which holds up to in_flight write requests of
# 64 KiB with their data. reductions and period_ns bind no erx_fs grant. The storage
# domain takes two connections, root's session and one more while a session is replaced,
# and root's session four: data, net, and one more for each while its server is
# replaced; a domain's system connection counts against no quota (life_connections,
# liberx/system/dom_life.c). The network domain, like the storage domain, takes two;
# the web domain holds its system connection alone, which its quota of one never meets.
# The machine's max_connections, 11, holds the six rows at rest (the system
# connections of root's session and of the three configured domains, and the session's
# data and net), the three a replacement session makes beside its predecessor's
# closing rows, and the two a restarted configured domain makes beside its own.
